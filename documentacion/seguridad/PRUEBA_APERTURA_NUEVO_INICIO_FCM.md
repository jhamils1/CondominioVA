# Apertura de alertas con el nuevo inicio FCM

Fecha: 2026-11-01 (America/La Paz). El usuario indicó que el aviso anterior abrió el perfil del guardia; ese ensayo utilizaba un controlador Flutter que podía retrasar la navegación. Se preparó una variante aislada ejecutada con inicio normal, sin controlador de integración, y un backend con base temporal y guardia ficticio.

En segundo plano, Firebase aceptó un aviso ficticio y el usuario confirmó que al tocarlo se abrió «Alertas de seguridad». Para probar el proceso cerrado se enviaron la aplicación a segundo plano y la orden Android `am kill`: en el primer intento el proceso seguía activo y no se envió ningún aviso; en el segundo se comprobó su ausencia antes de enviar el aviso ficticio. Firebase aceptó el aviso y el usuario confirmó que lo veía. El proceso había vuelto a iniciarse después de recibirlo, así que se terminó nuevamente y se comprobó su ausencia antes de pedir al usuario tocar el aviso.

El usuario confirmó que al tocar el aviso con el proceso cerrado apareció «Alertas de seguridad». Una captura temporal mostró esa pantalla con los dos avisos ficticios. El resultado se obtuvo sin controlador de integración ni liberación manual de fotogramas; no demuestra cuánto tarda en abrir ni el comportamiento con otras versiones de Android. La combinación respalda que el resultado anterior pudo estar relacionado con el controlador, pero no determina de forma definitiva la causa.

No se usó «Forzar detención», no se activaron envíos en el sistema habitual y los cambios de inicio siguen en la copia ignorada por Git. Se desinstaló la aplicación temporal con resultado `Success`, se retiró el enlace USB, se detuvo el servidor y se eliminaron la base ficticia, la captura y el registro de compilación. El paquete habitual no aparecía instalado en comprobaciones anteriores; no se determinó la causa. La entrega y apertura de la aplicación habitual siguen sin verificarse y el parche anterior de backend continúa desactualizado.
